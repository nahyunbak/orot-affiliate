# 템플릿 갱신 범위와 순서

기준: `nahyunbak/reading-app` main `8a0df3e85fc885b37a78819d185c7e0a4c20b215`. 대상 기준: `nahyunbak/full-template` main `a021476bb19fa260ce9ce33d7c24141d8422366c`.

## 사용자 확정 범위

- NestJS·Prisma만 유지한다. Firebase 전용 Web/Mobile·Firestore 생성 모드는 제거하고 FCM 푸시 SDK는 유지한다.
- Web·Mobile 모두 유지하며 제품 도메인을 전제하지 않는 최소 샘플 화면을 제공한다.
- 로그인·계정 관리·인앱결제·구독·광고·ATT·Sentry·Mixpanel·Meta·업로드·다국어·스토어 자동화를 유지한다.
- 계정·상품·광고·프로젝트 식별자는 `.env`로 설정한다. 실제 운영 자격증명·인증서·제품 에셋은 복사하지 않는다.
- Apple 영수증 검증을 위해 공식 `@apple/app-store-server-library` 의존성 추가를 승인받았다.

## 변경 순서

1. 수정 전 생성기·스캐폴드 테스트 24개로 기존 동작을 확인했다.
2. 공통 AGENTS 원문을 유지하면서 제품·계정·QA 고유 정보를 제거했다.
3. 독서·스크랩·퀴즈·캐릭터·라운지·재화·친구 도메인과 관련 에셋·문서·과거 제품 QA 이력을 제거했다.
4. 최신 main의 공통 서비스·Expo/RN 설정·Prisma를 분리했다. 인증·결제의 소유권 검증을 유지하고 익명 계정 연결에 인증 증명을 추가했다.
5. 기존 템플릿의 다중 대상·공개 API·제외 마커·백업 패키지를 유지하고 Nest 모바일 생성을 활성화했다. Service JSDoc부터 controller·DTO·fetch·query·mutation까지 생성 프로젝트에도 전달한다.
6. 환경변수·정책·실행 가이드를 정리하고 생성 프로젝트 3조합, 실제 로컬 API·Chrome PC/모바일 웹·네이티브 앱을 각각 검증한다.

최종 검증과 남은 제한, PR·QA 증거는 [작업 기록](../workhistory/2026-10-19.md)에 기록한다.

## 작업 경계

기존 로컬 저장소의 미커밋 변경은 건드리지 않고 별도 체크아웃에서 작업한다. 운영 배포·실제 과금·실제 푸시 발송·운영 DB 변경은 하지 않는다. DB 검증은 별도 로컬 빈 PostgreSQL에 수행한다. 개인 키와 운영 ID를 포함하지 않은 템플릿은 프로젝트별 외부 연동 설정 후 실통신 검증이 필요하다.
